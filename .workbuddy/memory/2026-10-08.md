# 2026-10-08

## 新建项目：外卖跑腿三端演示（waimai）

- 需求：像美团/饿了么的外卖跑腿系统，含导航、骑手取餐、商家端、聊天，前后端都要。
- 技术选型：Node 22 + Express 4 + ws（原生，无外部地图/支付依赖，零 API Key）。
  - 地图：Canvas 手绘城市路网 + 路口网格路径规划（`shared/city.js` 用 UMD 供前后端共用）。
  - 实时：WebSocket 推送 orders / riders / message；riders 每 500ms 一跳。
- 结构：`server/{index,sim,store}.js`、`shared/city.js`、`public/{user,rider,merchant}.html` + `js/{core,map,user,rider,merchant}.js`。
- 订单状态机：created → accepted → cooked → assigned → picking → delivering → arrived → completed。
  服务端 12 倍速模拟骑手移动（真实 5m/s），商家 4s 自动接单 + 15s 出餐，骑手到店/到达后 4s 自动取餐/送达。
- 三个端均可手动接管（商家关自动接单、骑手关自动取餐/送达并手动抢单）。

## 已验证

- `npm test`（test/smoke.js）：下单→送达全链路 54 秒跑通，聊天自动回复正常。
- `npm run test:dom`（test/dom.js，jsdom 真实执行）：三端零 JS 报错，下单/导航页/聊天/五个订单 Tab 均渲染正常。

## 踩坑记录

- `Nav.go` 必须先 appendChild 再 render，否则地图 canvas 的 getBoundingClientRect 为 0（尺寸失效）。
- 地图实例要挂在页面元素上（`pageEl._mv`），否则 track → 全屏导航页之间会串用同一个实例。
- 聊天页 render 签名漏写第三参 `pageEl`，jsdom 测试才暴露出来（浏览器同样会报错）。
- jsdom 里注入的 node fetch 不解析相对路径，测试需 `new URL(u, BASE)`；测试脚本末尾要 `process.exit(0)` 否则进程挂起。

### 本轮踩坑

- **Swift 闭包元组解构**：`ForEach(...) { a, b in }` 自 Swift 3 起已移除，必须写单参数再取 `.0/.1`。自查出 3 处（ChatView、CheckoutView 两处）。
- 环境有 HTTP_PROXY，curl/fetch 访问 `localhost:3000` 会被代理劫持返回 502 → 测试与文档统一用 `127.0.0.1`。
- `scripts/swiftcheck.py` 必须先剥字符串再剥注释，否则 `"http://..."` 里的 `//` 被当注释删掉，误报括号不平衡。
- iOS 无法在本机编译验证（Windows 无 Xcode），靠静态自检 + CI 日志迭代；已写好首次编译报错的降级方案（Glass.swift 换成 material）。

## 追加：切换身份要「可反复、可退出、不丢单」（第三轮需求）

- App：`switchRole` 改成先留快照（orders/messages/riders/cart）再 refresh，只有新数据非空才覆盖，
  网络异常拉空时回滚快照 → 切换身份绝不会把订单切没了。切换菜单底部加「退出登录」（免密，仅失效 token）。
- Web：新增 `public/js/roleswitch.js`，三端右下角悬浮「切换端」按钮（三端 + 入口页 4 个入口，标出当前端）。
  Web 端是游客模式，切换不输密码；App 端切换必须输密码。
- 新增 `test/switch.js`（20 项断言）：连续切换 5 次订单都在 / 骑手端能看到聊天 /
  错误密码不改身份且登录态不变 / 退出再登录订单与聊天照旧 / 切换期间配送状态机持续推进。
- 设计约定：**切换身份只换视角，不动业务数据**；退出登录只失效 token，服务端数据保留。这条要一直保持。

### 授权 / 推送

- GitHub CLI 默认 OAuth 只有 `repo` 权限，**改 `.github/workflows/*` 必须额外 `workflow` 权限**，
  否则 push 被拒（`refusing to allow an OAuth App to create or update workflow`）。
  解决：`gh auth refresh -h github.com --scopes workflow`（设备码授权）。
- `git push` 走 `credential.helper=helper-selector`（GCM）会弹窗卡死 → 直接用
  `git push https://x-access-token:$(gh auth token)@github.com/.../repo.git main` 绕开。
- 环境里的 HTTP_PROXY 不影响 github.com，代理和直连都能通。

### 构建踩坑（按遇到顺序）

1. **XcodeGen `--project` 是「生成到哪个目录」，不是工程文件路径**。
   传 `--project Waimai.xcodeproj` 会生成 `Waimai.xcodeproj/Waimai.xcodeproj` 然后 copy 报
   `The file "XcodeGen" doesn't exist`。去掉该参数即可（默认用 spec 所在目录）。
2. **Swift 编译错误 4 处**（本地静态自检抓不到，只能靠 CI 日志）：
   - `ToolbarItemPlacement.topTrailing` 不存在 → iOS 17 起叫 `.topBarTrailing`。
   - ChatView 里闭包元组改单参后遗留了 `k` 变量 → 改成 `item.0`。
   - `foregroundStyle(disabled ? .secondary : .white)`：三元两边必须同类型，
     `.secondary` 被推断成 `HierarchicalShapeStyle` 而 `.white` 只存在于 Color → 显式写 `Color.secondary / Color.white`。
   - `onChange(of:) { _ in }` 在 iOS 17 已废弃 → 改零参闭包。
3. **打 tag 自动传 Release 需要 `permissions: contents: write`**，否则 GITHUB_TOKEN 只读，
   softprops 报 `Resource not accessible by integration`。加在 workflow 顶层。
4. `push.tags` 与 `push.paths` 同时写也能触发（实测 v1.0.0 tag 成功触发构建）。

### 后端测试在 CI 上失败（真 bug，不是偶发）

- 现象：dom 测试里「订单跟踪页地图 canvas」本地必过、CI 必挂，等 10 秒也不出现。
- 排查：加诊断打印才发现 `doc.querySelector('.page')` 返回的是 **DOM 里第一个** .page（订单列表），
  栈顶是后追加的跟踪页，而它渲染成了「订单不存在」。
- 根因：下单接口返回后立刻 `go('track', {id})`，此时 WebSocket 还没把新订单推回来，
  `App.order(id)` 查不到。本地时序刚好相反所以没暴露。
- 修复：`submitOrder` 成功后先 `App.state.orders = [r.order].concat(...)` 做乐观更新再跳转。
- 顺带：test/dom.js 的固定 `wait(ms)` 全换成 `waitFor(fn, 10s)` 轮询，消除 CI 慢机偶发失败。

## 追加：用户报「服务器 404」→ 定位为默认地址未部署（第五轮）

- 根因：**`ios/Waimai/Core/API.swift` 里默认 baseURL 写的是 `https://waimai-api.onrender.com`，
  那只是预留的占位地址，Render 上从未部署过** → 实测 `https://waimai-api.onrender.com/api/bootstrap` 返回 404。
  本地服务是好的（`/`、`/user.html`、`/rider.html`、`/merchant.html`、`/api/*` 全部 200）。
- 本机局域网 IP：`192.168.1.220`（vEthernet (LAN)）。Git Bash 下 `ipconfig` 中文输出 grep 不到，
  用 Node 的 `os.networkInterfaces()` 查最可靠。Info.plist 已开 `NSAllowsArbitraryLoads`，
  App 连 http 不会被 ATS 拦。
- App 里改服务器地址的入口：`Auth/AuthView.swift` 的「服务器地址」菜单 + `App/RootView.swift:139`。
  **拿到线上域名后用户在 App 里填即可，不必重新打包 IPA。**

### Render 免费层现状（2026-10 联网核实）

- 仍在：免信用卡、512MB RAM / 0.1 CPU、750 实例小时/月、15 分钟休眠、冷启动 30–60 秒。
- **免费 PostgreSQL 30 天后过期**，且免费实例重启即清空磁盘 → 持久数据必须外挂
  **Supabase 免费 Postgres**；Supabase 免费项目 7 天无活动会暂停，需手动唤醒。
- 已为免费层做的适配：
  - `server/sim.js` 的 tick 拆成 `dirty`（推送）与 `persist`（落库）两个标记：
    骑手坐标每 500ms 变一次，**只有订单状态真正推进时才写库**，否则会把免费库写爆。
  - `server/store.js` 的 pg 连接池：`ssl` 由 `DB_SSL` 控制（默认开，本地自签可 `DB_SSL=0`），
    加 `max:4`、超时 10s、并监听 `error` 事件——不监听的话一次网络抖动就会让 Node 进程崩掉。
- 部署路径：`render.yaml`（Blueprint）已在仓库，Render Dashboard → New → Blueprint 一键部署，
  `DATABASE_URL` 是 `sync: false` 需手动填。用户已选「部署到 Render 免费版」，
  待其提供 Render API Key + Supabase 连接串后完成。
