# 2026-10-08

## 新建项目：外卖跑腿三端演示（waimai）

- 需求：像美团/饿了么的外卖跑腿系统，含导航、骑手取餐、商家端、聊天，前后端都要。
- 技术选型：Node 22 + Express 4 + ws（原生，无外部地图/支付依赖，零 API Key）。
  - 地图：Canvas 手绘城市路网 + 路口网格路径规划（`shared/city.js` 用 UMD 供前后端共用）。
  - 实时：WebSocket 推送 orders / riders / message；riders 每 500ms 一跳。
- 结构：`server/{index,sim,store}.js`、`shared/city.js`、`public/{user,rider,merchant}.html` + `js/{core,map,user,rider,merchant}.js`。
- 订单状态机：created → accepted → cooked → assigned → picking → delivering → arrived → completed。
  服务端 12 倍速模拟骑手移动（真实 5m/s），商家 4s 自动接单 + 15s 出餐，骑手到店/到达后 4s 自动取餐/送达。
- 三个端均可手动接管（商家关自动接单、骑手关自动取餐/送达并手动抢单）。

## 已验证

- `npm test`（test/smoke.js）：下单→送达全链路 54 秒跑通，聊天自动回复正常。
- `npm run test:dom`（test/dom.js，jsdom 真实执行）：三端零 JS 报错，下单/导航页/聊天/五个订单 Tab 均渲染正常。

## 踩坑记录

- `Nav.go` 必须先 appendChild 再 render，否则地图 canvas 的 getBoundingClientRect 为 0（尺寸失效）。
- 地图实例要挂在页面元素上（`pageEl._mv`），否则 track → 全屏导航页之间会串用同一个实例。
- 聊天页 render 签名漏写第三参 `pageEl`，jsdom 测试才暴露出来（浏览器同样会报错）。
- jsdom 里注入的 node fetch 不解析相对路径，测试需 `new URL(u, BASE)`；测试脚本末尾要 `process.exit(0)` 否则进程挂起。
