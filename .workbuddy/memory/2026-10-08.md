# 2026-10-08

## 新建项目：外卖跑腿三端演示（waimai）

- 需求：像美团/饿了么的外卖跑腿系统，含导航、骑手取餐、商家端、聊天，前后端都要。
- 技术选型：Node 22 + Express 4 + ws（原生，无外部地图/支付依赖，零 API Key）。
  - 地图：Canvas 手绘城市路网 + 路口网格路径规划（`shared/city.js` 用 UMD 供前后端共用）。
  - 实时：WebSocket 推送 orders / riders / message；riders 每 500ms 一跳。
- 结构：`server/{index,sim,store}.js`、`shared/city.js`、`public/{user,rider,merchant}.html` + `js/{core,map,user,rider,merchant}.js`。
- 订单状态机：created → accepted → cooked → assigned → picking → delivering → arrived → completed。
  服务端 12 倍速模拟骑手移动（真实 5m/s），商家 4s 自动接单 + 15s 出餐，骑手到店/到达后 4s 自动取餐/送达。
- 三个端均可手动接管（商家关自动接单、骑手关自动取餐/送达并手动抢单）。

## 已验证

- `npm test`（test/smoke.js）：下单→送达全链路 54 秒跑通，聊天自动回复正常。
- `npm run test:dom`（test/dom.js，jsdom 真实执行）：三端零 JS 报错，下单/导航页/聊天/五个订单 Tab 均渲染正常。

## 踩坑记录

- `Nav.go` 必须先 appendChild 再 render，否则地图 canvas 的 getBoundingClientRect 为 0（尺寸失效）。
- 地图实例要挂在页面元素上（`pageEl._mv`），否则 track → 全屏导航页之间会串用同一个实例。
- 聊天页 render 签名漏写第三参 `pageEl`，jsdom 测试才暴露出来（浏览器同样会报错）。
- jsdom 里注入的 node fetch 不解析相对路径，测试需 `new URL(u, BASE)`；测试脚本末尾要 `process.exit(0)` 否则进程挂起。

## 追加：iOS App + 账号系统 + 云部署（第二轮需求）

用户要求：做苹果 App、GitHub Actions 构建、支持液态玻璃、切换商家/骑手要输密码、可注册、云服务器选免费的。

- 技术选型依据（已联网核实）：
  - `macos-latest` 现指向 macos-26（macOS 26 + Xcode 26，iOS 26 SDK），液态玻璃 API 可用；macos-14 于 2026-11-02 退役。
  - 免费云：Fly.io（2024-10 起无免费计算）、Koyeb（仅剩免费 Postgres）、Railway（仅 $5 试用）均不可用；
    选 **Render 免费 Web Service**（免信用卡、支持 WebSocket 长连接）+ **Supabase 免费 Postgres**（永久免费）。
  - Render 免费实例休眠后磁盘清空 → store.js 做 Postgres/文件双后端，整库作为一个 JSON 文档存 `waimai_state` 表。
- iOS：`ios/` + XcodeGen（CI 里 `brew install xcodegen` 生成 xcodeproj，工程不入库避免 pbxproj 冲突）。
  16 个 Swift 文件约 2150 行：液态玻璃用 `#available(iOS 26.0, *)` + 毛玻璃降级；
  地图用 MapKit（虚拟米制坐标经 Geo.swift 映射成真实经纬度，与 Web 端同一套 x/y）。
- 账号：server/auth.js，crypto.scryptSync 加盐哈希 + 随机 token（30 天）；
  `/api/auth/verify` 供切换身份前二次验证密码；内置演示账号 demo/123456。
- CI：`.github/workflows/ios.yml`（macos-26，archive 不签名 → 打包未签名 IPA → artifact）；
  `.github/workflows/server.yml`（ubuntu，跑 smoke/auth/dom 三个测试）。仓库必须 Public 否则 macOS runner 收费。

### 本轮踩坑

- **Swift 闭包元组解构**：`ForEach(...) { a, b in }` 自 Swift 3 起已移除，必须写单参数再取 `.0/.1`。自查出 3 处（ChatView、CheckoutView 两处）。
- 环境有 HTTP_PROXY，curl/fetch 访问 `localhost:3000` 会被代理劫持返回 502 → 测试与文档统一用 `127.0.0.1`。
- `scripts/swiftcheck.py` 必须先剥字符串再剥注释，否则 `"http://..."` 里的 `//` 被当注释删掉，误报括号不平衡。
- iOS 无法在本机编译验证（Windows 无 Xcode），靠静态自检 + CI 日志迭代；已写好首次编译报错的降级方案（Glass.swift 换成 material）。

## 追加：切换身份要「可反复、可退出、不丢单」（第三轮需求）

- App：`switchRole` 改成先留快照（orders/messages/riders/cart）再 refresh，只有新数据非空才覆盖，
  网络异常拉空时回滚快照 → 切换身份绝不会把订单切没了。切换菜单底部加「退出登录」（免密，仅失效 token）。
- Web：新增 `public/js/roleswitch.js`，三端右下角悬浮「切换端」按钮（三端 + 入口页 4 个入口，标出当前端）。
  Web 端是游客模式，切换不输密码；App 端切换必须输密码。
- 新增 `test/switch.js`（20 项断言）：连续切换 5 次订单都在 / 骑手端能看到聊天 /
  错误密码不改身份且登录态不变 / 退出再登录订单与聊天照旧 / 切换期间配送状态机持续推进。
- 设计约定：**切换身份只换视角，不动业务数据**；退出登录只失效 token，服务端数据保留。这条要一直保持。
